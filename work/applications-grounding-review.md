## 1. P1 — Bind material narrative numbers to the same evidence used by metric cards

**Conference connection:** Kepler’s source/calculation/citation separation; OpenAI’s inspectable artifacts; the distinction between a supported figure and a fluent summary.

**Code-established current behavior:** Metric cards use `result_id`, column and row index ([schema](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/schemas.py:95)). Narrative and callout bodies are free strings; infographic values are also strings ([block schemas](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/schemas.py:111)). `_narrative` escapes/renders the supplied text without resolving quantitative claims ([renderer](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/renderer.py:188)); infographic values are escaped directly ([renderer](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/renderer.py:299)). `publish_findings` validates artifact references, but preserves the model-written `answer` ([publication](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/presentation.py:29)).

**Gap/inference:** A correct saved metric and an inconsistent number in the lead paragraph can coexist; evidence selection establishes access/lineage, not agreement between every material number and its rendered sentence. No such wrong production report was observed in this review.

**Incremental step:** Add typed numeric fact spans to the existing declarative report contract, using the same saved-cell/comparison resolver as metric cards. Start with quantitative headline/lead/callout claims and infographic values; keep ordinary explanatory prose free-form. Render the number and optional “how calculated” link from the binding, rather than asking an LLM to copy it correctly. This is preferable to a broad regex or another model claiming to verify arbitrary prose.

**Meaningful success measure:** In deterministic adversarial fixtures, changing the stored value or comparison must update every bound appearance, and a wrong/out-of-scope binding must fail before saving. Test rounding, negative and zero baselines, percentages, duplicated group rows, and conflicting headline/card values. Track unbound material numeric claims separately from binding-resolution failures; do not equate zero fixture failures with universal semantic correctness.

## 2. P1 — Preserve canonical metric identity through transparent saved-data transformations

**Conference connection:** A typed fact needs its meaning as well as its numeric value; correct arithmetic on a renamed or transformed measure is insufficient.

**Code-established current behavior:** Source SQL saves `grounding["metric_columns"]` ([execution](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/agents/text_to_sql/tools.py:133)). Tests already establish the intended rule: direct/CTE projections retain canonical identity, while multiplying the metric does not ([tests](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_semantic_grounding.py:420)). However, `query_saved_results` saves output lineage and SQL bindings without passing `metric_columns` ([saved SQL](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/agents/text_to_sql/tools.py:223)). The result store defaults missing metric bindings to `{}` ([store](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/datasets.py:220)). Comparison validation rejects a wrong canonical name only when a binding is present ([resolver](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/comparisons.py:80)).

**Gap/inference:** A harmless rename/projection of saved evidence can lose an enforceable semantic guarantee. A comparison can still disclose that identity was unverified, but cannot apply the same mismatch rejection as the original result. This is a loss of meaning across an otherwise preserved lineage path.

**Incremental step:** Extend the existing transparent-projection binding logic across saved-SQL inputs using their `sql_bindings` and `metric_columns`. Reuse SQLGlot already in the project. Propagate only unambiguous column projections; do not assign the old metric identity to scaled values, changed aggregates, ambiguous joins, or arbitrary Python outputs. Require an explicit reviewed definition for a newly computed measure.

**Meaningful success measure:** Fixture coverage must show identity survives pure projection, alias changes, filters, and transparent CTEs; identity must be withheld for `revenue * 2`, changed aggregation, or ambiguous lineage. A mislabeled comparison after a transparent reshape should fail just as it does for original source SQL. Existing comparison mismatch tests provide the acceptance pattern ([test](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_comparisons.py:138)).

## 3. P1 — Verify refresh equivalence at business grain, not only column shape

**Conference connection:** Time/source versions must travel with the fact; a refresh that changes what a row means is a different analytical input, even when its schema looks unchanged.

**Code-established current behavior:** `bind_refreshed_input` compares field names and physical Arrow types, reapplies the old filters, then copies the old grain label onto the refreshed input ([checks](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/presentation.py:186), [grain copy](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/presentation.py:204)). `AnalyticalInput.grain` is a string; non-upload dataset summaries supply a reminder to check business grain rather than a structured grain contract ([schema/summary](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/analytical_scope.py:49)). The refresh tests check changed columns/types and typed empty inputs ([test](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_saved_scope.py:723)).

**Gap/inference:** A regenerated dataset could retain column names/types while changing from one row per day/customer to another aggregation or duplicate population. The inspected refresh boundary does not establish grain equivalence before preserving the old description. Other guards constrain scope and some SQL fanout, but are not a general equivalence check between old and refreshed datasets.

**Incremental step:** For selected analytical inputs, persist an explicit key/time-bucket contract from the reviewed source or saved SQL and validate it during refresh. Compare declared keys, aggregation/date semantics, canonical measures, and source/scope identity; check key uniqueness on the full saved result. If equivalence cannot be established, request the already-supported scope clarification instead of relabeling the new data. Keep source cutoff unknown unless explicitly declared; do not infer it from maximum transaction date or save time.

**Meaningful success measure:** Add same-schema negative fixtures for daily-to-monthly aggregation, lost grouping keys, duplicate keys, and changed measure meaning. Reject them before publication while still accepting changed values and typed empty results at the same verified grain. Verify a legitimate refresh preserves categorical/date scope and creates a new result/report revision. Measure incorrect acceptance and needless rejection separately.

## 4. P2 — Apply the existing declared-unit rule to ordinary metric cards

**Conference connection:** A financial number is not fully grounded until its unit/currency is known. Formatting can introduce a false claim even when the stored value is correct.

**Code-established current behavior:** Period comparisons obtain units from a saved `unit_column` and reject free-text prefixes/suffixes ([resolver](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/comparisons.py:113)). Ordinary cards accept arbitrary `prefix` and `suffix` strings ([schema](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/schemas.py:105)) and concatenate them directly with the stored number ([renderer](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/renderer.py:265)). Unit/rate reconciliation has meaningful tests for comparisons ([tests](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_comparisons.py:94)).

**Gap/inference:** A standalone card could render an undeclared currency symbol or percent sign despite the coordinator/report-design instruction to preserve unspecified source units. This is a contract inconsistency, not an observed currency error.

**Incremental step:** Reuse the comparison unit-binding approach for standalone metric cards. Resolve a declared saved unit or reviewed semantic unit, preserve “source units” when unspecified, and keep purely stylistic numeric formatting distinct from unit claims. Explicit rate/percentage scaling should be a checked operation, not an arbitrary suffix.

**Meaningful success measure:** Reject a currency or percent label unsupported by evidence; correctly render declared currencies, unitless counts, ratios and percentage scales; preserve unknown units without inventing a symbol. Include mixed-currency and missing-unit fixtures, not only happy-path formatting checks.

## 5. P2 — Test the delivered HTML in a real rendering engine

**Conference connection:** Inspectability must survive export; verification at the data/spec layer does not establish that users can inspect the final chart or evidence disclosure.

**Code-established current behavior:** Report schemas validate design contrast, the renderer escapes model text, and generated HTML includes hashed CSP, inline chart logic, responsive CSS, theme toggles and print rules ([contrast](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/schemas.py:55), [interactive styling](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/renderer.py:573), [CSP](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/renderer.py:668)). `generate_report` immediately saves after rendering a string ([save path](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/data_analytics_agent/reporting/tools.py:155)). Inspected reporting tests check escaped output, HTML fragments, CSP and CSS tokens, including dark-mode tokens ([tests](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_reporting.py:89), [dark test](/Users/charlie/Repos/deepagents-agents/data-analytics-agent/tests/test_reporting.py:180)). No browser/screenshot execution was found in the reporting/UI tests inspected.

**Gap/inference:** Those checks cannot by themselves establish that inline Plotly scripts execute under CSP, theme changes update actual charts, a wide table remains usable on a phone, or printed evidence disclosures remain legible. No actual rendering defect is asserted without executing a browser.

**Incremental step:** Add a small offline, headless-browser acceptance suite over synthetic report fixtures using the existing report generator: scalar + comparison, wide table, statistical output, Plotly chart, and long labels. Keep browser QA in tests rather than making every user report depend on a costly visual agent. Check desktop/mobile, light/dark/adaptive, and print rendering.

**Meaningful success measure:** Require no browser console/CSP execution errors, populated chart traces, correct data/card text, working evidence disclosures, keyboard-operable theme toggle, and no unintended page-wide overflow at selected viewports. Check printed titles, tables, charts and calculation details for clipping. Retain a small set of visual baselines; expand only when a changed renderer introduces a new risk.

## Suggested order

Start with narrative fact binding and transparent metric-identity propagation: they reuse existing deterministic evidence paths and close gaps directly highlighted by the numerical-grounding talks. Add refresh grain equivalence next, then extend unit binding and browser artifact checks. This sequence grows the current working product rather than replacing its semantic layer or adding another general agent verifier.
